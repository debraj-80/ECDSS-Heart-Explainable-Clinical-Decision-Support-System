## 📌 Project Overview

ECDSS-Heart is an explainable clinical decision support system for heart disease risk prediction. It combines multiple machine-learning models through a stacking ensemble and provides feature-level and counterfactual explanations.

### Research Objective

To develop an interpretable machine-learning system that can predict heart disease risk while providing transparent explanations for its predictions, suitable for educational and research purposes.

### Dataset

The project uses the **UCI Heart Disease Dataset**, combining four databases:

| Database | Source |
|---|---|
| Cleveland | Cleveland Clinic Foundation |
| Hungarian | Hungarian Institute of Cardiology |
| Switzerland | University Hospital, Zurich |
| VA Long Beach | VA Medical Center, Long Beach |

**Input features (13):**

- Age
- Sex
- Chest pain type
- Resting blood pressure
- Serum cholesterol
- Fasting blood sugar
- Resting ECG
- Maximum heart rate
- Exercise-induced angina
- ST depression
- Slope of peak exercise ST segment
- Number of major vessels
- Thalassemia

**Target:** Binary classification

- `0` = No heart disease
- `1` = Heart disease

## 🧠 Methodology

```text
UCI Heart Disease Datasets (4 sources)
            ↓
      Data Cleaning
(type conversion, missing-value handling)
            ↓
     Target Conversion
   (binary classification)
            ↓
    Feature Engineering
(RPP, Thalach/Age Ratio, Log Cholesterol)
            ↓
    Train/Test Split
      (80/20 stratified)
            ↓
 Preprocessing Pipeline
(median imputation + standard scaling)
   [fit only on training data]
            ↓
    SMOTE-Tomek
 [training data only]
            ↓
       Base Learners
(Random Forest, XGBoost, CatBoost)
            ↓
   Stacking Ensemble
(Logistic Regression meta-learner)
            ↓
       Prediction
            ↓
       Evaluation
(Accuracy, Precision, Recall, F1,
 ROC-AUC, confusion matrix, ROC curve)
            ↓
      Explainability
       (SHAP + DiCE)
```

## 🔐 Data Leakage Prevention

The original prototype applied statistical preprocessing and resampling before the train/test split. This could allow information from the test set to influence model fitting and produce optimistic evaluation results.

The final implementation follows this order:

1. Load raw UCI data.
2. Apply type conversion and missing-value handling.
3. Create the binary target.
4. Add engineered features.
5. Split into training and test sets.
6. Fit imputation and scaling only on training data.
7. Apply SMOTE-Tomek only to the training split.
8. Keep the test set untouched for final evaluation.

This keeps the evaluation procedure separated from model fitting.

## 🔍 Explainability

### SHAP

**SHAP (SHapley Additive exPlanations)** is used to provide feature-level explanations.

- Shows feature contribution to predictions
- Provides feature-importance information
- Applied to the XGBoost base learner
- Used for clearer visualization

> SHAP analysis in this project explains the **XGBoost component**, not the complete stacking ensemble.

### DiCE

**DiCE (Diverse Counterfactual Explanations)** generates hypothetical counterfactual examples for individual predictions.

It can show how input features would need to change to obtain a different model prediction.

> Counterfactual examples are model-generated hypothetical scenarios and are **not medical advice**.

## 📊 Evaluation Metrics

| Metric | Description |
|---|---|
| Accuracy | Proportion of correct predictions |
| Precision | Proportion of positive predictions that were correct |
| Recall | Proportion of actual positives correctly identified |
| F1-Score | Harmonic mean of precision and recall |
| ROC-AUC | Area under the Receiver Operating Characteristic curve |

All reported metrics are calculated from actual predictions on the untouched test set.

## ⚙️ Feature Engineering

| Feature | Formula | Purpose |
|---|---|---|
| RPP | `thalach × trestbps` | Derived cardiovascular workload indicator |
| Thalach/Age Ratio | `thalach / age` | Normalizes maximum heart rate relative to age |
| Log Cholesterol | `ln(chol + 1)` | Reduces right-skew in cholesterol values |

### Pulse Pressure

True pulse pressure is:

```text
Systolic BP - Diastolic BP
```

The UCI dataset used here does not contain diastolic blood pressure. Therefore, true pulse pressure cannot be calculated.

The original prototype used:

```text
trestbps - trestbps.min()
```

This was not a valid physiological pulse-pressure calculation and has been removed from the final implementation.

## ⚠️ Limitations

- **Dataset Size:** The combined UCI dataset contains approximately 920 records, which is relatively small for machine-learning research.
- **Dataset Heterogeneity:** The four source databases were collected under different conditions and protocols.
- **Model Limitations:** This is a traditional machine-learning approach rather than a deep-learning system.
- **No Clinical Validation:** The model has not been externally validated on independent clinical datasets.
- **No Clinical Deployment:** The system has not been deployed or validated in a clinical environment.
- **Explainability Scope:** SHAP explanations are generated for the XGBoost base learner, while the final prediction comes from the stacking architecture.
- **No True Pulse Pressure:** Diastolic blood pressure is not available in the dataset, so true pulse pressure cannot be calculated.

## 🔬 Methodological Problems Identified and Fixed

### 1. Data Leakage

The original prototype applied SMOTE-Tomek before splitting the data.

**Fix:** Split the data first, then fit preprocessing and apply SMOTE-Tomek only to the training data.

### 2. Invalid Pulse Pressure

The original calculation:

```python
trestbps - trestbps.min()
```

does not represent pulse pressure.

**Fix:** The feature was removed because the dataset does not contain diastolic blood pressure.

### 3. Fabricated Evaluation Values

The original prototype contained hardcoded metric values and simulated ROC curves.

**Fix:** Metrics and ROC curves are now generated from actual model predictions on the untouched test set.
